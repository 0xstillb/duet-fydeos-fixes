# Lenovo Duet 5 KB — FydeOS Floss/HOGP repair

Status: root cause proven, source patches produced, and a reversible runtime bridge tested on this Live USB. The bridge now types and produces touchpad events and remained stable for 10 minutes. The patched daemon is still not built into the OS; the source-patch path remains the durable fresh-install fix.

## Root cause

`Duet 5 KB` is BLE HOGP. A direct Floss GATT read of Report Map handle 39 succeeds with exactly 512 bytes. SHA-256 is `262ed064b3a701846b7fd6eb4a7c7ce82ff2809cb1f1be71b42a07e1b30efd0b`. Byte 511 is `09`, the header of a HID short `Usage` item requiring one following byte. Linux therefore reports `item fetching failed at offset 511/512`, returns `-EINVAL` from `hid-multitouch`, UHID never becomes ready, and Floss fires `uhid_ready_disconn_timeout` before reconnecting.

The working pogo cover proves a long composite touchpad design: USB interface 1 has a valid 913-byte descriptor with five Finger collections. BLE uses a transport-specific merged descriptor, so it is not a literal prefix of the USB map. See `descriptor-comparison.txt`.

Installed Floss is `floss-0.0.2-r8327`, AOSP Bluetooth commit `85ccfbdb4f09b90bc1d7171ac77c979e9b299e2e`. Its `bta_hh_le_save_report_map()` only repairs one known Brydge descriptor via `INTEROP_HOGP_LONG_REPORT`. That repair appends a Brydge-specific 101-byte suffix and is selected only by DIS VID/PID. Lenovo reports `0000:0000`, so a config-only entry cannot safely select it. Do not add `0000:0000` and do not reuse the Brydge suffix.

## Repair

`patch/0001-FLOSS-HOGP-repair-Lenovo-Duet-5-KB-report-map.patch` applies to the exact installed revision. It matches the full received 512 bytes by SHA-256, so privacy-random addresses and missing VID/PID do not matter and unrelated descriptors are unchanged. It appends `descriptors/ble/lenovo-verified-residual.bin` (207 bytes), producing a 719-byte descriptor with SHA-256 `6d8472b344592896718356859ad9896eed46fa0e7738e93616a026bdfc23085f`.


The runtime loop had a second, independent trigger: native Floss HoGP background reconnect plus BAS discovery opened several GATT clients for the same privacy-addressed keyboard.  Patch `0002-FLOSS-Duet5-suppress-native-reconnect.patch` suppresses only the verified Lenovo report-map device from HoGP background reconnect and skips BAS discovery only when the bonded remote name is exactly `Duet 5 KB`; unrelated HID and battery devices keep the original behavior.

The residual completes contact four, adds contact five using an observed complete BLE contact template, adds the scan-time/contact-count/button tail verified against the working pogo descriptor, and closes the Application collection. Static validation shows balanced collections, no incomplete item, and a 192-bit/24-byte Report ID 6 input layout matching the live GATT characteristic.

The exact original BLE suffix cannot be read because GATT attributes max out at 512 bytes. The 207 bytes are a minimal functionally equivalent reconstruction, not a claim that the inaccessible firmware bytes are byte-identical.

## Build the smallest component

Use the FydeOS 23.0-SP1/ChromiumOS SDK checkout containing the exact AOSP Bluetooth commit above and the `amd64-fydeos_iris` board/sysroot.

1. Apply patches 0001 and 0002 at the AOSP Bluetooth checkout root.
2. Run the existing host test target `bluetooth_hh_test` and add a regression invocation of `bta_hh_le_save_report_map` if integrating upstream.
3. Rebuild `net-wireless/floss-0.0.2-r8327` for `amd64-fydeos_iris`. The affected deployed artifact is only `/usr/bin/btadapterd`; no kernel rebuild is involved. Typical SDK invocation is `emerge-amd64-fydeos_iris =net-wireless/floss-0.0.2-r8327` (use the board wrapper generated by that SDK).
4. Copy the built `btadapterd` out of `/build/amd64-fydeos_iris/usr/bin/btadapterd` and record its SHA-256.

The installed daemon already links `libcrypto.so.3`, and both `libbt-bta` and `bluetooth_hh_test` declare `libcrypto`, so the SHA-256 guard introduces no new package dependency.

## Live USB deploy and rollback

Do not run `install.sh` until the patched daemon has been built and tested in the SDK. The script refuses NVMe/MMC-looking root devices, backs up the exact original with mode/owner/timestamps and hashes under `/usr/local/duet-bt-debug`, stops only Floss hci0, replaces only `btadapterd`, starts hci0, and returns the root mount to read-only. The Downloads/MyFiles mount is `noexec`. First copy `install.sh` and `uninstall.sh` into `/usr/local/duet-bt-debug/` on the Live USB root, then run:

```sh
sudo /usr/local/duet-bt-debug/install.sh /path/to/patched/btadapterd
```

Rollback:

```sh
sudo /usr/local/duet-bt-debug/uninstall.sh
```

No interop rule is required. Bluetooth USB power remains `auto`. No bond wipe, firmware change, kernel change, or global autosuspend change is part of this repair.

## Running-kernel UHID validation

On 2026-09-15, `diagnostics/uhid-parse-test.py` submitted the repaired 719-byte descriptor to the running kernel through `/dev/uhid`. The kernel created HID device `0005:0000:0000.013C`, bound it to `hid-multitouch`, and created Keyboard, Consumer Control, System Control, and Touchpad input devices. No `item fetching failed at offset 511/512` or probe error `-22` occurred for the repaired device. The temporary ACL for user `chronos` was removed immediately afterward. See `logs/uhid-repaired-parser-test.log`.

This validates the reconstructed descriptor and kernel side of the repair. It does not replace the remaining requirement to build/deploy patched `btadapterd` and test real Bluetooth reports, typing, touchpad behavior, stability, and reconnects.


## Runtime bridge result (Live USB, 2026-09-16)

The tested fallback uses the repaired 640-byte UHID descriptor and a Floss GATT client. The running kernel created:

- event13: `Duet 5 KB Bluetooth bridge Keyboard`
- event22: Consumer Control
- event23: System Control
- event24: `Duet 5 KB Bluetooth bridge Touchpad`

The user typed `DUET LIVE 123`. A monitor that discarded payload contents observed 1,656 bytes on event13 and 203,952 bytes on event24. A 10-minute monitor completed with no new `GATT_CONN_TIMEOUT`, `item fetching failed at offset 511/512`, `probe error -22`, or `uhid_ready_disconn_timeout`.

The runtime package is not the final Floss source fix. It uses a bridge process plus a small watchdog that unregisters the known native Floss GATT clients while the bridge owns the Duet connection. It is reversible and board-specific. It does not wipe bonds or change firmware/kernel/Wi-Fi. It must be installed only after reviewing the scripts.

## Fresh FydeOS installation and fresh pairing

Fresh pairing will not recreate the 512-byte parser failure if the two source patches are built for the exact installed Floss revision: patch 0001 matches the full 512-byte map by SHA-256 and appends the verified residual; patch 0002 prevents the verified Duet from re-entering native HoGP/BAS reconnect competition. A new privacy address does not defeat the map hash guard. Do not wipe all bonds as part of the fix.

If the patched daemon cannot be built, the runtime fallback can be installed after a fresh FydeOS boot:

```sh
cd /home/chronos/user/MyFiles/Downloads/duet-fydeos-fixes/bluetooth-keyboard
bash install-live-bridge.sh
```

The script intentionally refuses internal/NVMe roots unless the operator explicitly sets `DUET_ALLOW_INTERNAL_ROOT=YES`. On an intended fresh FydeOS installation only, after checking `findmnt -no SOURCE /`, use:

```sh
sudo env DUET_ALLOW_INTERNAL_ROOT=YES bash install-live-bridge.sh
```

This backs up `/etc/init/btadapterd.conf`, installs the tested preload/bridge files under `/usr/local/duet-bt-debug`, adds an upstart bridge job, grants only the chronos `/dev/uhid` ACL, and does not alter Bluetooth power policy. Pair `Duet 5 KB` normally after the service is running; the bridge waits for the bonded name. For rollback:

```sh
sudo env DUET_ALLOW_INTERNAL_ROOT=YES bash uninstall-live-bridge.sh
```

For the durable fix, build `btadapterd` with patches 0001 and 0002 in the FydeOS 23.0-SP1 SDK, then use `install-fydeos-floss.sh` and `uninstall-fydeos-floss.sh` with the same explicit root confirmation. These scripts never wipe bonds and replace only `/usr/bin/btadapterd`.

The Downloads/MyFiles mount is `noexec`; copy scripts to `/usr/local/duet-bt-debug` or invoke them through `bash`, as shown above. Do not run either installer on the current Windows/NVMe setup without an intentional fresh FydeOS root and a verified backup.

## Boot Protocol

Protocol Mode handle 37 exists and is currently Report mode (`1`). Boot Keyboard Input handle 41 returns 8 bytes and Boot Mouse Input handle 46 returns 4 bytes. Floss exposes generic GATT writes but no HID-profile protocol switch, so no direct write was forced; the profile would not register matching boot notifications reliably. Boot Protocol is therefore documented but not used as the fix.
